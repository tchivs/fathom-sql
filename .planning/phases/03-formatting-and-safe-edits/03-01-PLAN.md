The formatter consumes the CST delivered by Phases 1-2: each Statement node wraps a family node (Select/Insert/Update/Delete/Merge/CreateTable/...) whose children are flat, ordered leaves — SourceTrivia (whitespace/newline/comment/BOM), SourceToken, SourceError, SourceSkipped (syntax.mbt:2-44). Token roles are re-derived from raw bytes via @token.classification_of (token.mbt:450-460) and byte shape; there is no per-token role stored in the CST. print_lossless (printer/printer.mbt:28) stays untouched — the formatter is a new package (D-27).

The defining contract of this plan: **the formatter is a token-sequence-preserving rewriter**. Same tokens in the same order; keyword spelling canonicalized through the classification table; inter-token whitespace canonicalized to a fixed alphabet; comment bytes emitted verbatim, never case-rewritten, never moved across a line boundary they did not already have (D-28/D-36). Nothing is dropped except whitespace runs between tokens. This makes idempotence hold by construction (research Pattern 2 / Pitfall 1).

Research is authority for mechanism (probe-verified libc is NOT needed here — formatter/ and api/ are pure; the only IO package in this phase is the CLI, which is plan 03-04); PATTERNS.md pins the exact analogs: ParseOptions constructor/accessor convention (api.mbt:19-118), ParseError named-field enum (51-62), PrimitiveDiagnostic shape (149-157), parse entry shape (250-300), printer leaf walk (printer.mbt:5-34), EmbeddedManifestFixture test convention (test/parser_test.mbt:463-505).

## Trust Boundaries

| Boundary | Description |
|---|---|
| Untrusted SQL input → formatter core | Adversarial or pathological CSTs must not hang, blow the stack, or emit partial output; format is a single forward pass with bounded work. |
| Error trees → refusal path | Refusal must surface the parse diagnostics (DORIS-PARSE-*) together with DORIS-FORMAT-001; it must never mask or swallow them. |
| Formatter core → api facade | The api layer owns the parse; the formatter receives only validated CSTs and never panics on slice failures. |
| Config values → FormatOptions | Invalid indent/line_width must fail construction (ASVS V5), never reach layout. |

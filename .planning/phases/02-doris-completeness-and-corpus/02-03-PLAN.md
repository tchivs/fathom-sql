**As a** maintainer and consumer, **I want to** inspect an auditable, versioned classification of reserved, non-reserved, and contextual Doris/MySQL-compatible keywords, **so that** valid non-reserved or contextual words remain usable as identifiers while version-invalid syntax is never accepted silently.

Purpose: Make DORIS-04 executable — the three-layer classification (D-14) becomes a data-driven table with per-row introduced_profile gates (D-15) and an auditable keywords.tsv report (D-16), with the official released-docs reserved list as the authority (D-13). Clause-position recognition stays per-family in the parser; this plan only classifies words for identifier/reserved decisions and version gating, leaving the shared recovery set untouched (research Pitfall 3).
Output: Data-driven classification table in token.mbt, corpus/keywords.tsv mirror, classification/version-gate tests, and correspondence enforcement.
</objective>

<context>
Phase 1 encoded three layers as functions (token.mbt ~199-258): is_clause_keyword (shared recovery boundary), is_reserved_word (clause keywords + a fixed operator/word list), and is_unquoted_identifier (negation). DORIS-04 requires this to become auditable and versioned: a data table where every parser-production word carries classification, introduced_profile, and source (D-13/D-14/D-15/D-16). The official reserved-keyword list is byte-identical across 2.1/3.x/4.x (research-verified), so versioning lives in feature-introduction metadata, exactly as DorisFeature gates do for MERGE (4.x) and QUALIFY (3.x). Words like BUCKETS, PROPERTIES, COMMENT, AGGREGATE, ENGINE, ROLLUP are grammar words absent from the reserved list → non-reserved (usable as identifiers). Contextual words (TABLET, QUALIFY, ROLLUP-in-clause) stay non-reserved. The keywords.tsv deliverable (D-16) is checked in and enforced to mirror the runtime table via an embedded correspondence test, so the audit artifact cannot drift. Behavior-preserving constraint: existing Phase 1 classification tests must keep passing, which anchors the table's initial content.
</context>

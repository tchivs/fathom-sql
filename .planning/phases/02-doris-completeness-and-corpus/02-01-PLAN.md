<objective>
**As a** Doris SQL consumer, **I want to** parse version-supported DML statements — INSERT (VALUES and query sources), UPDATE, DELETE, and 4.x-gated MERGE — inside semicolon-separated scripts under an explicit profile, **so that** a bad statement localizes its diagnostic without discarding later statements.

Purpose: Expand the Phase 1 SELECT-only kernel into DML with the keyword-first dispatcher (D-11), explicit unsupported-statement nodes (D-12), and version gates (D-15), in the locked priority order INSERT first, then UPDATE/DELETE, then MERGE last (D-09). Statement segmentation, monotonic statement_id, and statement-level panic-mode are reused unchanged, which is what makes DORIS-03 hold.
Output: Keyword-first dispatch, three DML statement parsers plus 4.x-gated MERGE, unsupported-statement nodes with DORIS-PARSE-007, new SyntaxKinds, api kind_id arms, and executable DML/DORIS-03 tests.
</objective>

## Trust Boundaries
| Boundary | Description |
|---|---|
| Untrusted SQL script → DML parser | Scripts may contain pathological statement floods, unclosed parens in VALUES/rows, and truncated clauses. |
| Selected profile → version gates | A consumer may submit MERGE under 2.1/3.x or PARTITION(*) under 2.1; gates must reject without silent acceptance. |
| Unknown statement starters | ALTER/DROP/GRANT/SHOW/EXPLAIN/LOAD/TRUNCATE/CREATE must become explicit error nodes, not identifiers or dropped bytes. |

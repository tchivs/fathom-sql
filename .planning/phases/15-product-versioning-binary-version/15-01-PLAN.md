Create `version/moon.pkg` (library; FFI externs cfg'd native-only so js/wasm builds never import it) and `version/version.mbt` with `pub fn product_version() -> String` returning exactly `"1.0.0"`, `pub fn version_line(name : String) -> String` returning `name + " " + product_version() + "\n"`, and a native-only `pub fn print_and_exit(name : String)` that writes `version_line` bytes to fd 1 (unbuffered) and calls `exit(0)` — used by the LSP binary. Add the `fathom/sql/version` import to `fathom-sql/moon.pkg` and `fathom-lsp/moon.pkg`; `fathom-lsp/moon.pkg` additionally imports `moonbitlang/core/env` for `@env.args()`.

In `fathom-sql/run.mbt` add `pub fn run_version(name : String) -> CliOutcome` returning exit 0 and stdout bytes = `@utf8.encode(@version.version_line(name))`, empty stderr. In `fathom-sql/main.mbt`, before parse_args and after the --help branch, add: if `rest.length() == 1 && rest[0] == "--version"`, write `run_version("fathom-sql").stdout` to fd 1 and `exit_process(0)`. Any other `--version` occurrence keeps the existing path (UnknownFlag -> exit 2 via parse_args).

In `fathom-lsp/main.mbt`, before `serve_stdio`, check `args.length() == 2 && args[1] == "--version"` and call `@version.print_and_exit("fathom-lsp")` (never falls through to the server loop).

Write `docs/VERSIONING.md` (English) recording VER-01: product semver policy (first public version 1.0.0; `fathom.*.v1` wire-contract stability commitment for the 1.x line; breaking changes require a contract-version bump such as `.v2` with a migration note; version bump process = change `version/version.mbt` product_version -> tag `vX.Y.Z` -> Phase 17 CHANGELOG entry; `moon.mod` module version stays `0.1.0` and is decoupled from product version per Phase 13 decision).
  </action>

| Boundary | Description |
|---|---|
| version constant -> binaries | 单一常量驱动两个发布二进制；篡改/漂移会破坏 tag 一致性。 |
| Binary output -> release tag assertion | 产物自报版本必须与发布 tag 匹配；不匹配即阻断 build。 |
| Policy doc -> external users | VERSIONING.md 是外部契约承诺，不得与实现漂移。 |

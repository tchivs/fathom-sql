## Trust Boundaries

| Boundary | Description |
|---|---|
| argv + file path → CLI | Bad flags, bad values, missing/unknown profile, and missing files must yield exit 2 with a message, never a crash or garbage output. |
| stdin/file bytes → libc FFI | Native String UTF-16 must never reach libc; reads must be bounded and handle short reads/EOF. |
| CLI → api core | The CLI is an untrusted-shell-facing adapter; format logic and diagnostics stay in core (D-38). |
| stdout/stderr/exit | Formatted SQL is the ONLY stdout content; diagnostics go to stderr; exit codes are exactly 0/1/2 (D-39). |

| T-03-23 | Denial of Service | Huge stdin/file input | medium | mitigate | Input size bounded by ParseLimits max_bytes (8 MiB) at the api entry; read loops are chunked and stop at EOF; InputTooLarge -> exit 1 with the parse error (parser.mbt:38-44). |
| T-03-24 | Information Disclosure | Data exfiltration | low | accept | The formatter is pure; the CLI writes only stdout/stderr and performs no network, no env reads beyond argv, and no file writes except nothing (read-only tool); no exfiltration surface exists. |
